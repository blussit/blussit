# Technical SEO Audit — 2026-10-06 (branch `blussit-v2`)

Audit of crawlability, indexing, metadata, structure, performance, structured
data and local SEO, with fixes applied and validated. Keyword strategy lives
in [SEO_KEYWORDS.md](SEO_KEYWORDS.md). Nothing here is deployed yet; the live
site still runs `main`.

**How it was checked:** a production build was served locally with a server
that applies `vercel.json` the way Vercel does (files first, then rewrites,
then `404.html` with status 404, trailing-slash redirect, gzip). Then:
- a no-JavaScript crawler read every sitemap URL and every internal link;
- headless Chrome rendered pages at 390 px and 1366 px;
- Core Web Vitals were measured on a mobile profile (4× CPU slowdown,
  1.6 Mbps, 150 ms RTT);
- the live production site was probed directly (redirects, headers, Googlebot
  user agent).

## 1. Architecture

React 19 SPA (Vite, React Router 7) on Vercel. Public pages are pre-rendered
to static HTML at build time (`scripts/prerender.mjs` + `src/prerender/entry.tsx`).
That HTML is the same React components rendered with the live catalogue
fetched at build, and the browser starts from the same data. Titles,
descriptions and canonicals come from one file, `src/seo/pages.json`, which
also generates `sitemap.xml`. Private portals stay client-rendered.
Canonical host: `https://blussit.com`.

## 2. URL inventory

**Indexable (15, all in the sitemap):** `/`, `/doorstep-car-wash-indore`,
`/services`, `/services/{jet-wash, star-wash, waterless-car-wash,
car-deep-cleaning, bike-wash}`, `/plans`, `/book`, `/about`,
`/service-policy`, `/cancellation-policy`, `/privacy-policy`, `/terms`.

**Not indexable:**
- **Blocked in robots.txt, plus noindex on the app shell:** `/app/*`,
  `/admin/*`, `/manager/*`, `/captain/*`, `/login`, `/forgot-password`,
  `/thank-you`, `/society/{token}`.
- **Build files behind clean URLs, blocked in robots.txt:** `/_pages/*`,
  `/spa.html`.
- **Real 404 + noindex:** unknown URLs and unknown service slugs.
- **`api.blussit.com`:** `X-Robots-Tag: noindex` on every response,
  robots.txt `Disallow: /`.

## 4. Status by area

- **robots.txt:** correct; allows CSS/JS/images; declares the sitemap; no
  contradictions with noindex or the sitemap.
- **Sitemap:** valid XML, 15 canonical HTTPS URLs, no duplicates, no private
  or preview URLs. Generated from `pages.json` on every build.
- **Canonicals:** exactly one per page in the raw HTML. It matches the
  sitemap and redirects. Query strings (e.g. `/book?service=…`) canonicalise
  to the clean URL.
- **noindex:** only on the private shell, the 404 page and the API host.
  There is no accidental noindex on a public page.
- **Titles and descriptions:** unique for every indexable page, 24–56 and
  66–162 characters, written from page content, present in raw HTML.
- **Headings:** one H1 on every content page.
  - The landing has two identical H1s (desktop and phone heroes), and only
    one is displayed at any size. Left as is: not competing, and a single H1
    would need a hero restructure.
  - `/book` has an H1 only after JavaScript (it's the booking app).
- **Internal links:** every indexable page is reachable through real `<a>`
  links (footer on every page; services ↔ service pages ↔ Indore ↔ plans ↔
  about), with no orphans and no broken links. The landing's service cards
  open booking via click handlers; their pages are linked from the footer.
- **Structured data:**
  - Site-wide Organization/LocalBusiness/AutoWash plus WebSite.
  - Per page: Service with offers (live price), BreadcrumbList (with visible
    breadcrumbs), FAQPage only where the same FAQs are visible, AboutPage,
    ItemList.
  - All JSON-LD parses; URLs match canonicals; values are escaped.
- **Security:** metadata comes from static config, never request input;
  JSON-LD and embedded data escape `<`; unknown slugs render 404 rather
  than echoing input; there are no open redirects.

## 5. Core Web Vitals (lab)

Measured on the mobile profile above, against a local HTTP/1.1 server. That
**understates production**: Vercel serves HTTP/2 (which honours the
`fetchpriority` hints) from a CDN. Each figure is the better of 2 runs.

| Page | FCP | LCP | CLS | TBT | Transfer |
|---|---|---|---|---|---|
| `/` | 1.41 s | 4.88 s (was 5.78) | 0.004 | ~930 ms | 859 KB (was 1,280) |
| `/services/jet-wash` | 1.46 s | 3.74 s | 0.000 | ~470 ms | 452 KB |
| `/doorstep-car-wash-indore` | 1.18 s | 1.18 s | 0.089 | ~410 ms | 334 KB |
| `/services` | 1.16 s | 4.78 s | 0.089 | ~290 ms | 719 KB |
| `/terms` | 1.24 s | 2.40 s | 0.011 | ~240 ms | 331 KB |

**Remaining risks:**
- **Image LCP:** on image-led pages it is bandwidth-bound on this profile.
- **Homepage main-thread time** (~930 ms at 4× CPU): the app re-renders the
  pre-rendered DOM rather than hydrating it. Switching to `hydrateRoot` would
  cut this but needs mismatch-proofing (motion and reduced-motion hooks,
  auth) — a follow-up.
- **CLS 0.089** on two pages comes from the web-font swap, still under 0.1.

Confirm real-world numbers with PageSpeed Insights after deploying.

## 10. Ranking expectations

No ranking can be guaranteed. Results depend on competition, the domain's
age and authority, reviews and the Business Profile, links, and Google's
systems.

What this work changes is the foundation. Every public page now has its own
title, description, content and links in the HTML Google first sees. Google
also gets honest status codes, a clean sitemap, and truthful structured
data. Expect movement over weeks after deploy and Search Console submission
— fastest for brand searches ("blussit car wash", "blussit indore").
